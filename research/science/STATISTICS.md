# Статистический модуль v1

Пакет `research_stats` запускается из корня checkout, Python 3.11+,
стандартная библиотека. Он не подключён к runtime, wheel/entry point движка,
символическим адаптерам или SQLite-журналам.

```bash
python -m research_stats distribution
python -m research_stats report research/science/examples/synthetic_study.json
python -m research_stats simulate --n 1000 --seed 20261016
python -m unittest discover -v
```

## Точная нулевая модель двух полей

В каждом поле фиксированы четыре различных выбранных числа из 1–20;
исход равномерно выбирает одно из `C(20,4)=4845` четырёхэлементных множеств.
Совпадения внутри поля неупорядочены; поля упорядочены и не объединяются.
Для K совпадений нужно выбрать k из четырёх отмеченных и `4-k` из 16 прочих:

`P(K=k)=C(4,k)C(16,4-k)/4845`, k=0,1,2,3,4.

| k | Число исходов | Точная вероятность |
| --- | --- | --- |
| 0 | 1820 | 1820/4845 |
| 1 | 2240 | 2240/4845 |
| 2 | 720 | 720/4845 |
| 3 | 64 | 64/4845 |
| 4 | 1 | 1/4845 |

Числители суммируются в 4845. `E[K]=4/5`, `Var(K)=256/475`.
**Только при независимости полей** совместное распределение — произведение
вероятностей, распределение суммы — свёртка; `E[K1+K2]=8/5`,
`Var(K1+K2)=512/475`, `P(K1=K2=4)=1/23474025`.
Ожидание суммы складывается и без независимости, но произведение вероятностей
и формула дисперсии суммы без ковариации её требуют.
Файл `examples/exact_distribution.json` содержит все 25 пар и 9 сумм
в виде точных дробей и десятичных представлений.

Это математическая модель. Название игры не присвоено: официальные правила,
межполевая/межтиражная независимость и фактическая равномерность не проверены.
Сравнение метода с контролем дополнительно учитывает зависимость их результатов
на одном исходе; нельзя объявить их независимыми выборками.

## Импорт и проверка

Машинная структурная схема: [import.schema.json](import.schema.json).
Дополнительные межзаписные проверки выполняет `research_stats.core.report`.

| Объект | Поля и семантика |
| --- | --- |
| Корень | schema_version=`dis-statistics-v1`, study_id, provenance=`SYNTHETIC/IMPORTED`, method_id, control_id, registered_at, analysis_at, events, predictions, outcomes; необязательно binary_event |
| Реестр events | event_id, registered_at, target_at. Включить **все** запланированные пробы, в том числе без прогноза/исхода |
| predictions | prediction_id, event_id, strategy_id, mode=`forecast/retrospective`, status=`PICK/ABSTAIN`, fixed_at, confirmation=`CONFIRMED/UNCONFIRMED`, evidence_ref, fields; необязательно probability |
| outcomes | event_id, occurred_at, recorded_at, confirmation, source_ref, fields |
| fields | Ровно два массива по четыре различных целых 1–20; bool/float/строки не допускаются. Одно число может встречаться в обоих полях |

Известные времена — ISO с явным смещением, сравнение в UTC. `null` означает
неизвестное время и сохраняется неизвестным: такая запись остаётся в отчёте для
описательного подсчёта и получает причину исключения `UNKNOWN_TIME`, поэтому не
входит в перспективную оценку. Study registration ≤ event registration ≤ analysis.
Если время цели, события и получения известны, исход обязан удовлетворять
target ≤ occurred ≤ recorded ≤ analysis.
Фиксация после analysis — ошибка импорта. Нужны ровно один event_id, один
исход на событие и максимум один вариант каждой зарегистрированной стратегии
на событие; дополнительные варианты регистрируются как отдельные исследования,
а не выбираются по удачному исходу. Неизвестные ключи, ID, стратегии,
невалидные числа, дубли и несогласованные времена отклоняют импорт целиком
с ненулевым кодом CLI. Исходный файл при этом не меняется.

Для каждой из двух стратегий на каждом событии создаётся строка, даже если
данных нет. `RETROSPECTIVE`, `LATE` (fixed ≥ target), `UNKNOWN_TIME`,
`REGISTRATION_VIOLATION`, `UNCONFIRMED` исключены из предварительной оценки,
но остаются в отчёте. Дополнительные признаки confirmation/status и причины
исключения сохраняются независимо от этой классификации. `ABSTAIN`,
`MISSING_PREDICTION`, `MISSING_OUTCOME`, `UNCONFIRMED_OUTCOME` дают `null`,
а не ноль попаданий. Известные описательные совпадения ретроспективных/
неподтверждённых проб выводятся в отдельном поле и не входят в тест.

`CONFIRMED` — **декларация импортёра** с непустой ссылкой на свидетельство.
Подписи/сертификаты TSA, неизменность внешнего реестра, источник исходов и
содержимое ссылок автоматически не проверяются. Локальный хеш входного файла
в CLI-отчёте считается по байтам экспорта после замены CRLF на LF и не удостоверяет
историческое время их появления. На Linux, где файл уже в LF, это те же байты файла.
Для реального испытания нужен независимый аудит до присвоения CONFIRMED.

## Парное сравнение и неопределённость

Основная демонстрационная метрика — разность суммарных попаданий двух полей
`D_i=(K_method,1+K_method,2)-(K_control,1+K_control,2)`, от −8 до 8.
Каждая пара должна относиться к одному event_id и одному исходу; обе стратегии
заранее зафиксированы и имеют допустимый режим. Отчёт показывает сами пары,
средние попадания **по полям**, размер выборки и исходный реестр непарных проб.
Вспомогательные разности по полям ограничены диапазоном [−4,4].

1. **Точный двусторонний тест знаков:** из n пар выделить W положительных,
   L отрицательных разностей, отдельно показать T нулевых. При нулевой
   гипотезе `P(D>0 | D≠0)=1/2` и независимых знаках
   `p=min(1, 2·Σ[k=0..min(W,L)] C(W+L,k)/2^(W+L))`.
   Если ненулевых пар нет, p=`null`. Тест проверяет вероятность выигрыша
   среди нетривиальных пар, **не равенство средних** и не размер выигрыша.
   Не нужна симметрия величин разности, но независимость событий и справедливая
   нулевая вероятность знака необходимы. Общие тиражи внутри одной пары
   учитываются парностью, зависимость между парами этим не устраняется.
2. **95% интервал Hoeffding для среднего эффекта:** для независимых
   `D_i∈[-B,B]`, B=8 (по полю B=4), полуразмах
   `h=2B·sqrt(log(2/alpha)/(2n))`; интервал
   `[mean(D)-h, mean(D)+h] ∩ [-B,B]`, alpha=.05. Он консервативный,
   может охватить весь диапазон при малой выборке; при n=0 интервал отсутствует.
   Для iid пар оценивается популяционное E[D]; для независимых неидентичных
   пар — среднее их ожиданий на заданной серии, без автоматического переноса
   на новые условия. При кластеризации требуется новый анализ, которого здесь нет.

Вывод общей ограниченной формы: для `Z∈[a,b]` вторая производная
`log E exp(tZ)` — дисперсия под экспоненциально наклонённой мерой, не более
`(b-a)^2/4`. Дважды интегрируя и центрируя, получаем
`log E exp(t(Z-EZ)) ≤ t²(b-a)²/8`. Независимость позволяет перемножить MGF;
неравенство Маркова и оптимизация по t дают
`P(|mean(D)-mean(ED)|≥h) ≤ 2exp(-2nh²/(2B)²)`.
Отсюда указанный интервал. Это отдельный математический вывод; прочитанная
страница CS229 формулирует только Bernoulli-случай, а не эту общую версию.

Предварительная регистрация метрики, alpha и остановки — условия применения.
Полевые тесты в отчёте помечены exploratory; для подтверждающих нескольких
гипотез нужны заранее заданное распределение alpha/коррекция и мощность.
Результат на выборке совместно ответивших методов может быть смещён отбором
воздержаний. Полный реестр и покрытие обязательны; интервал не устраняет это
смещение. Статистический модуль не выносит вердикт «эффективен» по сумме или p.

## Brier

Единственный поддержанный бинарный объект v1 —
`binary_event="field_1_contains_1"`: число 1 присутствует в **первом поле
исхода**, независимо от выбранных билетов. Метод и контроль предсказывают
один и тот же Y, иначе парное сравнение Brier было бы некорректным.
Для PICK можно записать `probability∈[0,1]` в том же заранее фиксируемом
пакете. Brier=`(p-Y)^2`, меньше лучше. Отсутствующее p не восстанавливается
из текста, поддержки ядер, попаданий или контрольной частоты; Brier=`null`.
Нет зарегистрированного binary_event при наличии p — ошибка. У ABSTAIN
оба поля и вероятность должны быть null.

Отчёт содержит отдельные пары Brier только на общих событиях с двумя
допустимыми вероятностями. Показанная средняя разность описательная;
отдельный тест/интервал Brier в v1 не реализован.

## Искусственные примеры и границы

В `synthetic_study.json` восемь событий и 16 ожидаемых слотов: включая
ретроспективу, неподтверждённый вариант, отсутствие прогноза, воздержание,
отсутствие исхода и позднюю фиксацию. Для метода допустимы 2 исхода,
для контроля 7, пар для сравнения только 2; нулевые попадания сохранены.
Все ссылки на свидетельства — явно синтетические заглушки.

`simulate` использует локальный `random.Random(seed)` и равномерный выбор
без возвращения независимо для двух полей. Это учебная псевдослучайная
модель, не криптографический RNG эксперимента, не реальный тираж, не
ретрокаузальность и не физическая петля времени. Один seed воспроизводит
результат в проверенных версиях Python; долговременные исследования должны
архивировать и версию Python, и выданные последовательности.

История переписки/тиражей не реконструировалась, в том числе из кратких
упоминаний в ENGINE_DESIGN. Для реальных данных требуется полная выгрузка
с фиксациями/источниками, восстановленный заранее заданный реестр всех
допустимых попыток и независимая проверка их происхождения. Пока этого нет,
никакая строка синтетического примера не является свидетельством эффективности.
