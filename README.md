# DIS Rune Oracle

Самостоятельный исследовательский проект Дмитрия Степанова.

Наша цель — создать Оракул, объединяющий символические традиции и научную проверку, чтобы исследовать возможность предсказания будущего со снижением измеряемой ошибки, проверить гипотезу обратного потока времени и выяснить природу удачи, отличая её от случайности.

## Текущее состояние — v0.3.1, 18.10.2026

Работает общий локальный цикл: регистрация события и конфигурации → руны,
механика И‑Цзин, Мо и Гуань Инь → ручная приёмка claims → роутер десяти ядер
с весами 0.10 → неизменяемый исходный отчёт → отдельные научные версии →
оценка исхода и контроль. Стандартная библиотека Python 3.11+, POSIX; без LLM/API.

[Единый CLI, учебный цикл и ограничения](docs/INTEGRATED_ENGINE_V0_3.md).
[Матрица готовности десяти ядер и фактические проверки](docs/INTEGRATION_REPORT_V0_3.md).
Научная стадия использует существующий `research_stats`; числа не выводятся из
символов автоматически. Толкования И‑Цзин, Мо и Гуань Инь остаются ABSTAIN;
историческая процедура выбранного храма не подтверждена. Добавлены условные
модели Maya/Name Grids и ручные регистраторы Shakuna/Slavic с ABSTAIN; их
исторические источники и корпуса не подтверждены (доступ через прокси 403).
Daliuren/Egypt остаются UNAVAILABLE. Веса не перераспределяются; прогнозных
голосов без явной ручной приёмки нет.

Добавлен [календарный контекст рун](docs/RUNE_CALENDAR_CONTEXT.md): японское
рокуё и адаптер древнеегипетского Каирского календаря. Он сохраняет традиционные
метки дня отдельно от голосов десяти ядер. Японская лунная дата и современное
соответствие египетской даты задаются явно; без входов/локального корпуса — ABSTAIN.
Это не меняет статус прогнозного ядра Egypt и не доказывает влияние даты на исход.

30.10.2026 добавлены [лаборатория сочетаний и стратегический модуль v1](docs/LAB_AND_STRATEGY_V1.md).
Лаборатория заранее фиксирует сравнения рун, календаря и восточных толкований с
частотным и случайным контролем; отсутствующие компоненты сохраняют ABSTAIN.
Стратегический модуль считает матрицы решений и равновесия двух участников в
чистых стратегиях. Культурные заметки сохраняются отдельно от полезностей и
вероятностей. Реальная серия нового исследования ещё не запускалась.

[Аудит четырёх ядер и исправления science/review v0.3.1](docs/FOUR_CORE_AUDIT.md):
время создания научного отчёта отделено от cutoff, исправления исхода связаны
явной цепочкой, несовместимый review отклоняется до записи.

Технические тесты не доказывают прогнозную эффективность; гипотеза обратного
потока времени остаётся непроверенной. Независимое контролируемое исследование
не проведено. Предыдущие версии, научная карта и аудит сохранены отдельно.

## Быстрый запуск

Из корня репозитория:

```bash
python -m unittest discover -v
python -m dis_oracle cycle-demo --directory /tmp/dis-v03-demo
python -m dis_oracle verify --db /tmp/dis-v03-demo/state/cycle-v03.sqlite3
python -m dis_oracle compare examples/mixed.json
python -m dis_oracle calendar-context examples/calendar_context/input.synthetic.json
python -m dis_oracle lab-demo --directory private-runs/lab-demo-1
python -m dis_oracle strategy examples/strategy/decision.synthetic.json
python -m dis_oracle strategy examples/strategy/game.synthetic.json
python -m dis_oracle freeze examples/aligned.json --run-id demo-1 --db private-runs/demo.sqlite --markdown private-runs/demo-1.md
python -m dis_oracle evaluate examples/outcome.json --run-id demo-1 --db private-runs/demo.sqlite
python -m dis_oracle verify --db private-runs/demo.sqlite
python -m dis_oracle summary --db private-runs/demo.sqlite
```

`cycle-demo` требует новый пустой каталог и явно использует SYNTHETIC данные
и моделируемое время исхода, не реальный прогнозный опыт.

Пример `aligned.json` имеет режим `analysis`: его исход не учитывается как предварительный прогноз. Повтор `freeze` без `--markdown` возвращает ту же запись без дубля; существующий файл отчёта не перезаписывается.

## Границы

Руны ведут изложение без повышенного числового веса. Недоступные доли не перераспределяются. Согласие не является вероятностью или измеренной точностью. Метки ACCEPTED требуют указанного человека-рецензента; v0.1 не удостоверяет его личность и не проверяет достоверность источников. Движок не публикует, не платит, не делает ставок и не запускает команды из текстов.

Журнал запрещает замену записей через сервис и SQLite-триггеры, но администратор может переписать базу. Цепочка хешей без независимой фиксации не доказывает время создания. Личные записи остаются вне Git; папка `private-runs` и базы SQLite исключены из репозитория.
