# Единый рабочий цикл ОРАКУЛА — 04.11.2026

`python -m dis_oracle.workflow` заменяет разовые скрипты для обычного учёта
тиражей. Python 3.11+, стандартная библиотека; интегрированный символьный цикл
использует POSIX. Команды не обращаются к сайту, не покупают билеты и не читают
исход целевого тиража из сети. Номер и время события вводит оператор.

## Что фиксируется

Одна локальная SQLite-база хранит последовательность операций с хеш-цепочкой.
Операция записывается целиком в транзакции. Параллельные команды блокируются;
повтор той же команды возвращает тот же расклад, включая случайный контроль.
Другие входы для уже зафиксированного номера отклоняются. Отменённый расклад
нельзя сгенерировать заново. После ввода результата отмена запрещена, чтобы
не исключать неудачи из оценки. Исправление результата добавляет запись с
хешем прежней версии и причиной; исходная запись остаётся.

Ключ события — **игра + номер**, а не время или соседний тираж. Повторное
использование комбинации на другом тираже не переносит исходный прогноз.
Старые описательные сводки с таким использованием сохранены отдельно.

В каждом новом раскладе есть три независимых слота:

| Метод | Источник | Ограничение |
| --- | --- | --- |
| `frequency100-v1` | Последние до 100 допустимых результатов этой игры, полученных журналом до фиксации | Всегда показывает фактическое `n`, номера, частоты и хеш истории; при нехватке данные не выдумываются |
| `lottery-rune-hash-v2` | Неизменяемый символьный цикл, затем прежнее авторское SHA256-сопоставление | Без шаблона — ABSTAIN; преимущество не доказано |
| `random` | Равномерная выборка четырёх различных чисел в каждом поле | Фиксируется вместе с другими слотами, повтор команды не меняет контроль |

Конфликтный `hunt:47129` исключён из частот и чистых сравнений, но сохранён.
Результаты разных игр не смешиваются. Записи без допустимого времени получения
не проходят частотный расчёт; при миграции время получения — фактическое время
импорта, а старое `recorded_at` сохраняется только как заявление источника.

По умолчанию пропуск более пяти номеров между последним допустимым результатом
и целью блокирует создание. Это проверка полноты по номерам, **не подтверждение
расписания**. Осознанное исключение `--max-history-gap N` сохраняется во входах.
Нельзя создать расклад, если уже известен результат того же или большего номера
этой игры, либо наступило объявленное время цели. Перевод часов назад
относительно последней записи отклоняется.

## Работа с архивом и новым тиражом

Из корня репозитория; пути с пробелами заключайте в кавычки. В командах ниже
`DRAW` заменяется фактическим целым номером, `TARGET` — ISO-временем с зоной,
например `2027-01-01T20:40:00+03:00`. Примеры не запускают реальную серию.

```bash
python -m dis_oracle.workflow --db private-runs/oracle.sqlite3 migrate /path/Oracle_2026-10-22_archive_and_run.zip
python -m dis_oracle.workflow --db private-runs/oracle.sqlite3 verify
python -m dis_oracle.workflow --db private-runs/oracle.sqlite3 report
python -m dis_oracle.workflow --db private-runs/oracle.sqlite3 forecast hunt DRAW TARGET --template examples/workflow/manifest.json
python -m dis_oracle.workflow --db private-runs/oracle.sqlite3 outcome hunt DRAW /path/outcome.json
python -m dis_oracle.workflow --db private-runs/oracle.sqlite3 backup /path/new-backup.sqlite3
```

Для второй игры используется `four_of_twenty`. Файл исхода содержит:

```json
{"fields":[[1,2,3,4],[5,6,7,8]],"source":"описание полученного источника","occurred_at":"2027-01-01T20:40:00+03:00"}
```

`occurred_at` необязателен; неизвестное время не подменяется догадкой.
Повтор тех же чисел не меняет источник/время. Конфликтные числа требуют
`--correction-of HASH --reason "причина"`, где HASH — поле `outcome_hash` из команды
`python -m dis_oracle.workflow --db private-runs/oracle.sqlite3 show hunt DRAW`.
CLI отчёт содержит признак исправленного исхода. Для отмены до получения результата:

```bash
python -m dis_oracle.workflow --db private-runs/oracle.sqlite3 cancel hunt DRAW "причина пользователя"
```

JSON с повторяющимися ключами отклоняется. Ошибка команды даёт JSON
`state=REJECTED` и код возврата 2; ошибку нельзя принимать за новый расклад.

Шаблон в `examples/workflow/manifest.json` явно задаёт доступные цифровые
процедуры. Цикл фиксирует собственный номер, время цели, случайные руны и дату
Maya по московской гражданской дате. Культурные голоса не преобразуются в числа.
Внешний блок `numeric_study` в шаблоне запрещён, чтобы не копировать чужие
прогнозы. Старый `calendar_context` не переносится на новую дату автоматически.
Факты шаблона — заявления оператора, не проверенные системой источники.

Символьные журналы лежат рядом: `oracle.sqlite3.cycles/`. Если сбой произошёл
после их фиксации, повтор использует прежний цикл; подмена шаблона отклоняется.
**Резервируйте и базу, и каталог `.cycles`** после завершения команд. Команда
`backup` создаёт согласованную копию основной базы с учётом WAL, но не копирует
каталог символьных циклов. После перезапуска нужны оба, чтобы сохранить полную
проверяемость символьного источника. Не удаляйте незавершённые циклы ради новых
комбинаций. Хеш-цепочка не защищает от владельца, переписавшего весь журнал.

## Серия исследования

До начала серии зарегистрируйте отдельный план JSON:

```json
{
  "study_id":"hunt-frequency100-series-1",
  "hypothesis":"Среднее число совпадений frequency100-v1 выше случайного контроля",
  "game":"hunt",
  "method":"frequency100-v1",
  "metric":"within_field_hits",
  "control":"random",
  "sample_size":100,
  "starts_at":"2027-01-01T00:00:00+03:00",
  "ends_at":"2027-02-01T00:00:00+03:00"
}
```

```bash
python -m dis_oracle.workflow --db private-runs/oracle.sqlite3 register /path/protocol.json
python -m dis_oracle.workflow --db private-runs/oracle.sqlite3 forecast hunt DRAW TARGET --study-id hunt-frequency100-series-1 --template examples/workflow/manifest.json
```

Изменение плана требует нового ID и будущего периода. Для рунического метода
укажите `lottery-rune-hash-v2`. Отменённые слоты входят в лимит набора; отчёт
отдельно показывает отмены, ожидания, воздержания и исправления. Серии не
объединяются в основной итог: `study_summaries` разделены по ID. Общие `groups`
служат только эксплуатационному описанию. Не меняйте правила после просмотра
неудач. Программа не обеспечивает независимость участников или независимое
подтверждение источников.

`combination_lab.py` сохраняет отдельную лабораторию сочетаний A/B/C/D и
контролей; этот слой не подменяет её протокол и не переносит туда старые успехи.
Для исследования времени следующий необходимый шаг — заранее определить
проверяемое событие, критерий, план анализа и независимую фиксацию обязательства
до события. Локальные часы, SHA256 и GitHub-код сами по себе не удостоверяют
время старых прогнозов и не доказывают предвидение. Реальная новая серия здесь
не запускается без известных будущих целей и заполненного плана.

## Перенос старых данных

Мигратор читает только JSON из ZIP и не выполняет старые скрипты. Повтор того же
ZIP идемпотентен; конфликтующие значения отклоняются. Исходный ZIP нужно хранить
для полных старых источников. Сводки прошлых лет сохраняются как исторические
публикации, но новый пересчёт использует только имеющиеся оригиналы с тем же
номером. Одна строка старой сводки без исходной комбинации не превращается в
нулевой или выдуманный прогноз: она попадает в `legacy_reconciliation`.

В технической проверке: синтетические сценарии повторов, параллельных команд,
просрочки, исправлений, отмены, восстановления после сбоя, подмены шаблона,
порчи журнала, переноса и резервной копии. Эти проверки подтверждают поведение
программы, а не рост числа совпадений.

## Окно 30 результатов — 05.11.2026

По явному запросу можно выбрать `forecast ... --frequency-window 30`. Это
отдельный метод `frequency30-v1`; по умолчанию остаётся 100. Выбор фиксируется
во входах до генерации. Повтор с другим окном отклоняется; старые запросы с
окном100 сохраняют прежнюю идентичность. Метод30 имеет собственную группу
отчёта и может быть заранее зарегистрирован. Окно содержит последние30
**имеющихся допустимых** результатов; оно не гарантирует30 подряд и не
восстанавливает пропущенные исходы. Фактический список всегда сохранён.
