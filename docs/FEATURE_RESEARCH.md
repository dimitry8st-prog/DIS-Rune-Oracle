# Исследовательский режим ablation признаков — feature-research-v1

Отдельный журнал и CLI. **Не изменяет** стандартную выдачу `workflow`,
`combination_lab` или `lottery-rune-hash-v2`. Гипотеза о связи символических
входов / времени события с исходом **не предполагается истинной**; режим только
фиксирует прогнозы до события и сравнивает заранее объявленные варианты.

```bash
python -m dis_oracle.feature_research --db private-runs/feature-research.sqlite3 register examples/feature_research/protocol.synthetic.json
python -m dis_oracle.feature_research --db private-runs/feature-research.sqlite3 forecast examples/feature_research/forecast.synthetic.json
python -m dis_oracle.feature_research --db private-runs/feature-research.sqlite3 outcome hunt DRAW examples/feature_research/outcome.synthetic.json
python -m dis_oracle.feature_research --db private-runs/feature-research.sqlite3 evaluate --study-id STUDY
python -m dis_oracle.feature_research synthetic-demo --directory /tmp/feature-research-demo
```

На Windows укажите локальный пустой каталог вместо `/tmp`.

## Что сохраняется до события

- игра и номер тиража;
- заявленное время события, IANA-часовой пояс, UTC;
- время формирования прогноза; отдельно — `data_received_at` (доступность данных);
- происхождение символического входа: `PROGRAMMATIC_RANDOM` / `MANUAL` / `OTHER` / `SYNTHETIC_FIXTURE`;
- исходные результаты других ядер в `core_results` (хранение, не голос);
- явные признаки, реально использованные каждым методом;
- версия метода, параметры (`min_train`, `shrinkage_alpha`, окно частоты);
- хеш обучающей выборки;
- прогнозы A–F и случайный контроль внутри A.

Неизвестные даты **не** восстанавливаются по номеру тиража.

## Варианты A–F

| ID | Содержание |
| --- | --- |
| A_random | Равномерный контроль 4-из-20 × 2 поля |
| B_frequency | Частоты по прошлым исходам той же игры (окно 30/100) |
| C_lottery_rune_hash_v2 | Точная базовая формула; только draw + rune_id + orientation |
| D_time_features_only | Авторская регуляризованная модель по бинам времени/календаря |
| E_rune_features_only | Та же модель только по явным руническим токенам |
| F_rune_plus_time | Руны + время |

Календарные метки берутся из существующего `calendar_context`, если переданы.
Новые бины часа/дня недели помечены как **авторская гипотеза**.
Простое добавление времени в SHA-256 **не** называется обучением: хеш у C — для
воспроизводимого авторского отображения; у D/E/F — аддитивные Laplace/ridge
частоты по прошлым совпадениям признака. При нехватке данных метод возвращает
`недостаточно данных` (ABSTAIN), а не выдуманную уверенность.

Другие культурные ядра подключаются отдельными вариантами только при корректных
входах; в v1 они сохраняются в `core_results`, но не становятся автоматическими
руками прогноза.

## Защита оценки

- игры и поля разделены; совпадения считаются только внутри соответствующих полей;
- прогноз запрещён, если известен исход того же или большего номера;
- повтор с другими входами отклоняется; точный повтор возвращает ту же запись;
- протокол регистрируется до окна исследования; смена правил — новый `study_id`;
- основной показатель: сумма совпадений внутри двух полей (0…8);
- дополнительно: гистограммы 0–4 по полям, покрытие, пропуски, разница с A;
- `--confirmatory-after` отделяет исследовательский период от удержанного;
- множественность: шесть методов; победитель post hoc не объявляется подтверждением;
- перестановка сохраняет двухполевую структуру totals; ограничения документированы.

Совпадения ≠ денежная прибыль. Отсутствие значимости ≠ доказательство отсутствия связи.

## Синтетический пример и архив

`synthetic-demo` использует только синтетические ряды. Реальные скриншоты, билеты
и личный архив в публичный репозиторий не входят. Если локального архива нет —
это ограничение явно указывается в отчёте демо.

Технические тесты подтверждают проводку режима, а не прогнозную эффективность.
