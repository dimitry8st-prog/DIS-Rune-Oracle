# DIS Rune Oracle — черновик кейса

**Символическая рефлексия с прозрачной процедурой и проверкой результата.**

Автор и владелец проекта: **Степанов Д.А.** Дата: **09.10.2026**. Статус: **проектирование методики; программный MVP не реализован**.

## Задача

В неоднозначной ситуации человек может застревать в одном объяснении, смешивать наблюдения с ожиданиями и откладывать следующий шаг. Убедительная AI-интерпретация способна усилить уверенность, даже когда у неё нет фактических оснований.

DIS Rune Oracle — самостоятельный проект ДИС для исследования этого класса задач. Цель — организовать переход от символического образа к нескольким возможным объяснениям, затем к конкретному действию и наблюдаемому результату.

Исходная гипотеза проекта: ограниченная символическая процедура может помогать рефлексии. Эффект ещё не измерен. Представление о многослойном прочтении используется как способ рассматривать ситуацию через факты, переживания, символы и действия; оно не служит доказательством отдельной физической модели реальности.

## Предлагаемое решение

Три закрытых элемента формируют последовательность: ситуация → возможный курс → возможное изменение. Пользователь может раскрыть вопрос или оставить его при себе. Первоначальное чтение фиксируется и сохраняется при последующем уточнении темы.

| Элемент | Для чего нужен |
| --- | --- |
| Закрытый выбор | Разделить процедуру получения знаков и их последующее толкование |
| Протокол ориентаций | Показать исходное положение, действие пользователя и применённое чтение |
| Предварительная фиксация набора | Сделать проверяемым отсутствие замены элементов после выбора |
| Несколько перспектив | Рассмотреть альтернативы, сохраняя различие фактов и метафор |
| Следующий шаг | Перевести разбор в обратимое действие или наблюдение |
| Дневник | Сопоставить первоначальную гипотезу с исходом и учитывать промахи |

Пример планируемого сценария: человек решает, стоит ли напомнить о предложении. После чтения он формулирует два объяснения молчания, выбирает корректное напоминание и назначает срок проверки. Результат оценивается по ясности решения, действию и фактическому ответу. Этот пример иллюстрирует замысел, а не описывает проведённое испытание.

## Критерии следующего этапа

Минимальный прототип должен фиксировать набор до выбора, корректно учитывать ориентации, позволять независимую проверку хеша и сохранять первоначальное чтение. Приватный режим не должен требовать раскрытия вопроса. Страница результата должна отделять известное, метафору, гипотезу и проверку.

Для оценки полезности нужен контрольный разбор без рун и вариант с нейтральными символами. Оценка доверия или ощущения совпадения не заменяет оценку конкретного действия и прогнозной ошибки.

## Ограничения

Символическая интерпретация не определяет диагнозы, правовые выводы, инвестиционные решения или поведение других людей. Повторный жребий не подтверждает истинность ответа. SHA-256 не обеспечивает случайность и не устанавливает прогностическую способность. Методика допускает ошибки интерпретации и требует проверки на реальных низкорисковых сценариях.
