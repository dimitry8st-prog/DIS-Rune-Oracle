# Political Event Impact v0.1

Исследовательский прототип измеряет наблюдаемую реакцию цен вблизи времени публичного сообщения. Первый сквозной пример содержит одно синтетическое событие и один синтетический контроль. Команда принимает локальные JSON, поэтому источник сообщения и рыночных данных должен быть указан при подготовке входов.

## Воспроизведение

Из корня репозитория выполнить:

```bash
python -m examples.political_event_impact.demo --directory /tmp/pei-demo
python -m dis_oracle.political_event_impact --db /tmp/pei-demo/study.sqlite3 freeze /tmp/pei-demo/freeze.json
python -m dis_oracle.political_event_impact --db /tmp/pei-demo/study.sqlite3 evaluate /tmp/pei-demo/evaluate.json
python -m dis_oracle verify --db /tmp/pei-demo/study.sqlite3
python -m unittest tests.test_political_event_impact -v
```

Команда генерации ожидает новый каталог. Команды журнала допускают точное повторение. Изменить запись под существующим ключом нельзя. Для новой оценки укажите новый `evaluation_id`. Времена в синтетическом примере относятся к модельному событию. SQLite отдельно хранит фактическое время записи в журнал.

## Контракт входов и защита времени

- Событие содержит идентификатор, автора, тип, HTTPS-адрес источника, время публикации и время наблюдения, SHA-256 заголовка и затронутые активы. При наличии текста заголовка его байты сверяются с хешем. Тема и неожиданность принимаются как пометки исследователя.
- Протокол фиксирует актив, бенчмарк, площадку, календарные границы обычных сессий, локальную зону IANA, контрольные времена, метрику и правило остановки. У каждого входного бара M1 есть начало, конец, время доступности, OHLCV, источник и признак синтетики. Все временные отметки данных указываются в UTC.
- При фиксации проверяется хронология регистрации, публикации, наблюдения и отсечения. Допустимы только завершённые до публикации M1, доступные к отсечению. Реакционные бары принимаются при оценке. Оценка отклоняет бары, доступные позже её среза, и попытки заменить исходный бар. Хеши связывают результат с входами.
- Контроли указываются до расчёта по тому же локальному дню недели и времени в полностью завершённых сессиях. Исследователь указывает источник отбора окон без политического события. Прототип проверяет временные критерии. Подтверждение отсутствия иных новостей остаётся задачей исследователя. Правило остановки включает все заявленные контроли.

## Измерения

Для окон 1, 5, 15, 60 минут берутся соответствующие полные M1 до и после публикации. Если она пришлась на середину минуты, эта минута исключается. Замер после новости начинается с открытия первого полного бара. В отчёте видны задержка получения новости и исходная граница замера. Первая реакция внутри исключённой минуты остаётся ненаблюдаемой. Сессии не склеиваются.

Доходность окна равна `close_last/open_first - 1`. Сверхдоходность равна разности доходностей актива и бенчмарка. Реализованная волатильность равна корню из суммы квадратов минутных лог-доходностей от открытия первого бара через последовательные закрытия. Её изменение равно разности после и до события для одинаковых по длине окон. Основная метрика — изменение волатильности актива на M60 за вычетом среднего изменения в зарегистрированных контролях. Отдельно доступны волатильность бенчмарка и сверхдоходность относительно контролей. Величины выражены в долях единицы, без годовой нормировки.

Первая реакция отмечается на первом закрытии M1, где абсолютная сверхдоходность от открытия постокна достигает 10 б.п. Далее отдельно фиксируются возврат внутрь диапазона ±10 б.п. и движение за противоположные 10 б.п. Времена измеряются от публикации. При пропусках данных, нулевом объёме, плоском ряде или выходе за пределы сессии окно получает ABSTAIN. При недостающем зарегистрированном контроле сравнительная метрика остаётся пустой.

Пилот даёт описательную метрику одного события. Для оценки эффекта и интервала неопределённости понадобится серия независимо размеченных событий и заранее зарегистрированный контроль. Следующий этап охватывает верификацию исторических источников M1 и времени первого появления сообщения, затем отдельную методику для +24 часов и walk-forward.
