# Лаборатория сочетаний и стратегический модуль · v1

Дата реализации: 30.10.2026. Основание: `155ca9c`, календарная ветка v0.3.1.
Два независимых дополнения работают локально на стандартной библиотеке Python.
Новая лаборатория регистрирует будущие сравнения; стратегический модуль помогает
сравнивать действия в заданных пользователем условиях. Старые циклы, фиксированные
веса десяти ядер и внешняя формула `lottery-rune-hash-v2` сохраняются.

## Лаборатория

Сначала фиксируется протокол: игра, даты начала/окончания, максимальное число
тиражей, требуемые восточные ядра, версии их корпусов, календарные профили и
список исключённых спорных исходов. Повторная регистрация возвращает ту же запись;
изменение правил требует нового исследования, зарегистрированного до его начала.
Размер серии задаёт исследователь; программа не определяет достаточность выборки
и не проводит расчёт статистической мощности.

| Вариант | Входы | Правило v1 |
| --- | --- | --- |
| A | Три исходные руны | Точная прежняя внешняя формула `lottery-rune-hash-v2` |
| B | Руны и зарегистрированные календарные профили | Авторская хеш-функция сочетания |
| C | Руны и зарегистрированные восточные толкования | Авторская хеш-функция сочетания |
| D | Руны, календарь, восточные толкования | Авторская хеш-функция сочетания |
| frequency20 | 20 последних доступных предшествующих исходов этой игры | Сохранённое правило `frequency20-v1` |
| random | Системный генератор | Четыре разных равновероятно выбранных числа в каждом поле |

Хеш-сочетание — **авторская проверяемая гипотеза перевода**, а не восстановленная
историческая формула и не обученная модель. Её качество не установлено. Веса ядер
и вероятности из этих хешей не выводятся. В новом эксперименте календарные признаки
участвуют только в B/D; исходный `calendar_context` остаётся культурным контекстом
и не получает прогнозного голоса в старом роутере.

Для A строка `lottery-rune-hash-v2|target=N|id:orientation,...` точно сохраняет
прежний порядок трёх позиций и Python-представление `None` пустого знака. Для каждого
поля выбираются четыре минимальных SHA256 от `seed|field=F|number=n`, затем числа
сортируются. Для B/C/D seed имеет вид:

```text
lottery-combination-hash-v1|game=GAME|draw=N|arm=ARM|features=SHA256_CANONICAL_FEATURES
```

Признаки содержат идентификаторы/ориентации рун; для календаря — идентификатор и
версию профиля, метку, традиционное качество дня и части дня. Современная дата и
время вычисления не добавляются как числовой «коэффициент удачи». Для восточных
ядер используются версия процедуры, зарегистрированный корпус и единственный
принятый поддерживаемый сценарий. Порядок профилей/ядер фиксируется протоколом.

При отсутствии любого обязательного компонента соответствующий вариант получает
`ABSTAIN`, `fields=null` и причину. Нет перераспределения весов или подстановки
ответа другого ядра. Для восточной части требуются `status=OK`, ручная приёмка
прогнозного утверждения, отсутствие ожидающих проверки/противоречивых утверждений
и совпадение `raw_result.text_corpus` с записью протокола. Запись корпуса содержит
`corpus_version`, `corpus_sha256`, `source_ref`; `null` означает недоступность.
Совпадение этих деклараций не удостоверяет подлинность корпуса или рецензента.

**Текущие реальные И-Цзин, Мо и Гуань Инь сохраняют ABSTAIN:** их законченные
исторические толкования ещё не предоставлены. Лаборатория не снимает это ограничение.
В учебном примере корпус и прогнозные утверждения полностью вымышлены и помечены
`SYNTHETIC`. Успех учебного запуска не доказывает готовность традиционных корпусов.

### Фиксация и проверка

В `lab-freeze` передаются `game`, `draw`, `target_at`, копия `original-report.json`
из завершённого цикла и нормализованный `history`. Структура одной строки истории:

```json
{"game":"hunt","draw":999,"fields":[[1,2,3,4],[5,6,7,8]],
 "available_at":"2026-10-30T10:59:03+00:00","source":"Ссылка на исходную архивную запись"}
```

`available_at` — время доступности записи исследованию, не предполагаемое время
тиража. Неизвестное время нельзя заполнять задним числом. Все строки должны быть
из той же игры, с меньшим номером тиража и доступны к cutoff исходного цикла.
Повторы и конфликты отклоняются. Пропуски номеров сохраняются: двадцать последних
доступных исходов не обязательно являются двадцатью последовательными тиражами.
Спорные номера исключаются по заранее зарегистрированному списку; для нынешнего
архива при проектировании исследования нужно учесть конфликт «Охоты» №47129.

Один исходный цикл нельзя выдать за несколько испытаний. Протокол должен быть
зарегистрирован до создания/фиксации чтения, фиксация лаборатории — до цели, в том
числе после завершения вычислений. Время хранится с часовым поясом и сравнивается
в UTC. После начала генерации контрольного варианта действует локальная блокировка;
параллельный точный повтор возвращает ту же сохранённую запись. Изменённые входы
не принимаются. Результат тиража добавляется отдельной неизменяемой записью.

Основная метрика — сумма совпадений **в соответствующих полях**, 0..8.
Основное заранее закреплённое сравнение — D−A на одинаковых завершённых тиражах.
Дополнительные парные сравнения: B−A, C−A, D−random, A−random, frequency20−random.
Отчёт показывает все регистрации, незавершённые исходы, пропуски и покрытие каждого
варианта. Пропуск не считается промахом. Разные по составу серии не ранжируются
по одним лишь суммарным совпадениям. Выводы остаются описательными, без p-value,
автоматического изменения весов и заявления о превосходстве над случайностью.

Существующие исходы архива можно использовать для подготовки входов и поиска ошибок.
Их нельзя задним числом превратить в предварительно зарегистрированную проверку
нового сочетания. Реальная серия ещё не запущена этим изменением.

### Команды

```bash
python -m dis_oracle lab-demo --directory private-runs/lab-demo-1
python -m dis_oracle lab-register protocol.json --db private-runs/lab.sqlite3
python -m dis_oracle lab-freeze trial.json --study-id MY-STUDY --db private-runs/lab.sqlite3
python -m dis_oracle lab-evaluate outcome.json --study-id MY-STUDY --db private-runs/lab.sqlite3
python -m dis_oracle lab-summary --study-id MY-STUDY --db private-runs/lab.sqlite3
python -m dis_oracle verify --db private-runs/lab.sqlite3
```

Учебный пакет `dis_oracle/lab_demo.json` показывает полные структуры протокола,
входов и исхода. Команда `lab-demo` требует новый пустой каталог и явно использует
моделируемые часы. Подстановка времени через Python API разрешена только для
`SYNTHETIC`; команды реального исследования такой возможности не предоставляют.

## Стратегический модуль

Формат `oracle-strategy-v1` поддерживает два вида задач:

1. `decision`: варианты действий, состояния среды и полная матрица полезности.
   Рассчитываются максимин, минимакс сожаления, строго доминируемые действия.
   Ожидаемая полезность считается только при явно заданном распределении состояний.
   Вероятности проверяются как точные десятичные дроби, без вывода из символов.
2. `game`: ровно два участника, их доступные действия и полезности обоих участников
   для каждой пары действий. Перечисляются все равновесия Нэша в чистых стратегиях.
   При их отсутствии модуль сообщает `NO_PURE_EQUILIBRIUM`; это не утверждение
   об отсутствии смешанного равновесия. Смешанные стратегии v1 не вычисляет.

Ничья, несколько равновесий и различия критериев сохраняются. Автоматического
выбора единственной рекомендации нет. Полезность — заданная пользователем оценка,
обозначенная как предположение либо наблюдение со ссылкой и временем доступности.
Она не объявляется установленным фактом или денежным прогнозом.

`cultural_notes` связывает расчёт с атрибутированными руническими, календарными и
восточными заметками. Их роль — сохранить интерпретации и вопросы для обсуждения.
Текст заметок не меняет матрицу, факты или вероятности. Так можно сопоставлять
символические сценарии с уже заданными действиями, не принимать метафору за факт
о намерениях партнёра. Даты, действия и полезности вводит и проверяет человек.

```bash
python -m dis_oracle strategy examples/strategy/decision.synthetic.json
python -m dis_oracle strategy examples/strategy/game.synthetic.json
python -m dis_oracle strategy my-decision.json --db private-runs/strategy.sqlite3
```

Без `--db` выполняется только просмотр. С `--db` сохраняется неизменяемый снимок
по `decision_id`; пересмотр предположений требует нового идентификатора. Пример
решения сравнивает запуск, пилот и ожидание в вымышленных условиях: максимин
выбирает ожидание, минимакс сожаления — пилот. Игровой пример — учебная дилемма
заключённого. Числа в обоих примерах вымышлены, не являются оценкой проектов Дмитрия.

## Ограничения исполнения и источники

Оба модуля выполняют расчёты и локальные записи. Нет модели/API, сетевых загрузок,
секретов, публикаций, ставок, платежей, рассылок или запуска команд из входных
текстов. Внешний JSON и строки источников рассматриваются как данные. Валидация
предшествует генерации случайного контроля; входы/правила/исходы разделены в журнале.
Отказ возвращает ошибку, незаполненный компонент — ABSTAIN. Отдельные пространства
ключей `lab:*` и `strategy:*` не меняют исходные циклы. Для отключения дополнения
достаточно не вызывать новые команды. Приватные данные остаются вне Git.

Хеши и блокировки защищают целостность локального процесса, но не удостоверяют
время, авторство и истинность источников. Независимая фиксация времени, проверенные
корпуса, определение размера серии/эффекта и контроль множественных проверок
потребуются для подтверждающего исследования. Измеренный прогнозный эффект не
представлен; гипотеза обратного времени этим изменением не проверяется.
