# Интегрированный цикл v0.3

Python 3.11+ на POSIX (блокировка `fcntl`), стандартная библиотека, без
сервисов, LLM, ключей API и новых runtime-зависимостей. Из checkout установка
не нужна: `python -m dis_oracle --help`. Пакет включает `research_stats` и
учебный JSON; console entry point `dis-oracle` сохраняется.

## Запуск полного учебного цикла

Из корня checkout, в **новый** каталог (команда не перезаписывает результаты):

```bash
python -m dis_oracle cycle-demo --directory /tmp/dis-v03-demo
python -m dis_oracle verify --db /tmp/dis-v03-demo/state/cycle-v03.sqlite3
```

Это синтетическое событие, четыре механические процедуры, явный ручной отказ
Гуань Инь без нового жребия, ручная приёмка пустого набора claims, исходный
отчёт, научный отчёт до исхода, учебный исход и новый научный отчёт.
Исход задан на 2099 год с **явным моделируемым временем**, чтобы не выдавать
демонстрацию за уже проведённое перспективное исследование.
`original-report.json`, `science-before.json`, `evaluation.json`,
`science-after.json` создаются отдельно. Рунический манифест не раскрывается.

Категориальный прогноз: ABSTAIN. Числовой пример: одна пара заранее указанных
**внешних синтетических** вариантов и контроля; это не перевод рун в числа.
Один удачный пример не доказывает эффективности; вероятность его выбора и
порядок остановки не являются исследованием популяции.

Те же стадии отдельными командами (другой новый каталог):

```bash
python -m dis_oracle cycle-start examples/v0_3/manifest.json --directory /tmp/dis-v03-manual --run-id teaching
python -m dis_oracle cycle-step examples/v0_3/qiuqian-refusal.json --directory /tmp/dis-v03-manual --run-id teaching
python -m dis_oracle cycle-step examples/v0_3/qiuqian-finish.json --directory /tmp/dis-v03-manual --run-id teaching
python -m dis_oracle cycle-review examples/v0_3/review.json --directory /tmp/dis-v03-manual --run-id teaching
python -m dis_oracle cycle-freeze --directory /tmp/dis-v03-manual --run-id teaching
python -m dis_oracle cycle-science examples/v0_3/science-before.json --directory /tmp/dis-v03-manual --run-id teaching
python -m dis_oracle cycle-evaluate examples/v0_3/outcome.json --directory /tmp/dis-v03-manual --run-id teaching --at 2099-01-01T00:00:02Z
python -m dis_oracle cycle-science examples/v0_3/science-after.json --directory /tmp/dis-v03-manual --run-id teaching
python -m dis_oracle cycle-status --directory /tmp/dis-v03-manual --run-id teaching
python -m dis_oracle verify --db /tmp/dis-v03-manual/cycle-v03.sqlite3
python -m dis_oracle export --db /tmp/dis-v03-manual/cycle-v03.sqlite3
```

Каждая команда печатает JSON. Два запуска с одинаковым manifest/run_id возвращают
сохранённые процедуры, включая перезапуск Python. После дальнейших команд
`cycle-start`/`cycle-status` показывают текущее состояние; повтор отдельной
`cycle-step` возвращает снимок именно этой команды, даже если сессия продолжена.
Повтор `cycle-demo` в непустой каталог отклоняется; для воспроизведения используйте
новый каталог, для продолжения — команды стадий. Случайные руны и цифровые жребии
между **разными** демонстрациями могут различаться. Повтор внутри сессии их не меняет.

## Конфигурация и стадии

[Полный учебный manifest](../examples/v0_3/manifest.json) задаёт:

- `schema_version: integrated-cycle-v0.3`, `provenance: SYNTHETIC | IMPORTED`;
- `event` по прежнему контракту: идентификатор, оси, альтернативы, дедлайны,
  baseline, факты с временным отсечением;
- `adapters`: любое подмножество `rune`, `yijing`, `mo`, `qiuqian`;
- `source_refs`: явно указанные ссылки происхождения;
- опциональный `numeric_study`: явный импорт зарегистрированных вариантов
  `dis-statistics-v1`, без исходов при регистрации. Не генерируется из символов.

Регистрация фиксирует весь manifest до генерации и создаёт привязку event_id к
одному run_id в этом журнале. Другой run_id для того же события отклоняется;
изменение manifest, в том числе `1` на `1.0`, тоже. Это локальная защита от
перебора сессий; создание другой базы и сокрытие попыток она не исключает.
Для исправленного опыта нужны отдельные идентификаторы и явная связь в источниках;
исходный опыт не удаляется. Все поля проверяются до первого случайного действия.

Для рун фиксируются три различных слота 1..25 и целые повороты 0/180.
Сохраняются закрытый commitment и карта чтения. Частично выполненный выбор
продолжается с сохранённого места. Это современное описательное чтение v2.1.
И‑Цзин: явный `manual` с шестью тройками целых 2/3 либо `digital` без throws.
Традиционное чтение и закреплённый runtime-корпус отсутствуют.

Мо: `manual` с двумя упорядоченными бросками 1..6 либо `digital` без ручных
значений. Все 36 числовых сочетаний допустимы; соответствия слогам нет.
Гуань Инь: авторский числовой набор 1..100; `manual` требует stick_number,
`digital` его запрещает. `max_attempts` — общее число подтверждений, включая
результат при старте: целое 0..1000, технический верхний предел.
Нулевой лимит завершает без подтверждения, противоречивое наблюдение отклоняется.

`cycle-step` допускает одну команду `confirm` (ручной результат), `advance`
(одно цифровое моделирование) или `finish` (явное завершение без подтверждения).
Все команды требуют неизменяемого request_id. Цифровая модель 筊杯 предполагает
две **независимые равновероятные стороны**, отсюда вероятности sheng=1/2,
yin=xiao=1/4; это допущение модели, не измеренные вероятности храма.
Отказ сохраняется, палочка не меняется, автоматического перевыбора нет.
`pending`, `confirmed`, `no_confirmation` различаются. Можно зафиксировать
отчёт с pending — механика останется незавершённой, прогноз не появится.
Исторические режимы Мо/Гуань Инь заблокированы; процедура выбранного
Kwan Im Thong Hood Cho Temple не подтверждена.

## Ручная смысловая приёмка

`cycle-review` требует объект `claims_by_core` со списками claims существующего
контракта. Пустой объект — явное воздержание. Карточки процедур сохраняются
отдельно; слой приёмки изменяет только claims, не текст, inputs или raw_result.
Фрагмент должен присутствовать в сохранённом толковании; ACCEPTED/REJECTED
требуют человека и времени, не предшествующего чтению. Freeze дополнительно
проверяет время приёмки относительно момента фиксации и дедлайна.

Только явные принятые человеком FORECAST участвуют в роутере. Сама механика,
SYMBOLIC, советы или PENDING не превращаются в прогноз. Нельзя повысить
ABSTAIN Мо/И‑Цзин/Гуань Инь до OK, вписать отсутствующий текст или claims
недоступного ядра. После review новые команды процедуры запрещены; после freeze
изменять исходный отчёт нельзя. Новые научные версии не заменяют старые claims.
Противоречия и неподтверждённые claims сохраняются и блокируют уверенный выбор
по правилам существующего роутера. Вес каждого ядра остаётся 0.10.

## Научный интерфейс

`cycle-science` принимает `report_id`, обязательную причину `reason`, опционально
`supersedes` (ID существующего научного отчёта) и полный снимок `numeric_outcomes`.
Результат хранится отдельной записью, с хешем исходного отчёта и регистрации.
Одинаковый ID и запрос возвращают прежний снимок, даже после получения исхода;
для нового расчёта нужен новый ID. Изменение запроса под старым ID отклоняется.
Научная поправка числового исхода — новая версия с причиной и ссылкой на прошлую;
категориальный исход engine.evaluate не заменяется этим интерфейсом.

Для категорий используется прежний `engine.evaluate`: ошибка 0/1 относительно
заранее зарегистрированного axis.baseline. Пропуски и ABSTAIN остаются null,
ретроспективные оценки не входят в перспективную эффективность. Научная стадия
вызывает **реальную** `research_stats.core.paired_summary` с bound=1 для разницы
`control_error - method_error`. Положительное значение означает преимущество
метода; название поля PR3 `mean_method_minus_control` сохранено ради совместимости,
направление явно указано в отчёте. При нескольких осях одного события интервал
и тест не вычисляются: оси нельзя считать независимыми опытами.

Это отчёт одного события, а не агрегированное исследование эффективности.
Для одной пары 95% интервал Хёффдинга охватывает весь [-1,1]; при нуле пар
метрика/интервал отсутствуют. Парный точный тест знаков предполагает независимые
ненулевые знаки с P(+)=1/2 при H0, относится к вероятности выигрыша без ничьих,
а не к равенству средних. Для интервала нужны независимые ограниченные пары и
заранее заданные отбор/остановка; пропуски способны сместить выборку.

Для числового импорта вызывается **реальная** `research_stats.core.report`.
В v0.3 мост ограничен одним событием/осью с совпадающими event_id и target_at.
Варианты, контроль, вероятности (если есть) фиксируются manifest до адаптеров.
Исходы нельзя подавать при регистрации. После исхода numeric_outcomes должны
соответствовать зарегистрированному событию и времени категориального исхода.
Две независимые математические задачи (категория и 4-из-20) не отождествляются.
Конкретные числа и их контроль пользователь импортирует явно.

Сохраняются все слоты двух стратегий, промахи, воздержания, отсутствующие исходы,
поздние/ретроспективные/неподтверждённые записи. Точное распределение, парные оценки
по полям и сумме, неопределённость и правила Brier остаются из PR3.
Доли поддержки ядер не являются вероятностями. Brier вычисляется только для
заранее явно записанного p и зарегистрированного бинарного события.

Отчёт содержит происхождение, версии протоколов/хешей корпуса, хеш исходника
`research_stats.core`, источники, времена фиксации/исхода, статус опыта,
метрики/n/контроль/неопределённость, ошибки валидации и непроверяемые утечки.
Ошибочный запрос отклоняется, запись отчёта не создаётся; отклонённые запросы
не являются валидными пробами и отдельно этим API не журналируются.

## Сохранность и ограничения

Общий каталог содержит экспортируемый `cycle-v03.sqlite3` и **отдельные**
private/.../rune.sqlite3, mo.sqlite3, qiuqian.sqlite3. Приватный рунический
манифест не попадает в общий export. Не используйте этот каталог для старых БД:
их перенос или миграция не требуется. Команды не изменяют прежние журналы.
Блокировка каталога сериализует операции интеграционного CLI, адаптеры сохраняют
свои транзакции и идемпотентные снимки. Прерывание между хранилищами восстанавливается
повтором той же команды; новой случайной процедуры не создаётся. Приёмка проверяет,
что снимок механики не изменился перед freeze.

SQLite-триггеры и хеш-цепочки обнаруживают изменения через штатный API и
повреждение сохранённых записей. Администратор может заменить всю БД/хвост
цепочки; независимой TSA, удостоверения личности и проверки факта исхода нет.
Это контроль воспроизводимости, не доказательство физической причинности.
`--at` разрешён только для SYNTHETIC; реальный IMPORTED цикл использует локальные
часы и требует внешней фиксации для исследовательских выводов.

Источника **lottery-rune-hash-v2** среди файлов проверенных веток нет. Статус
UNAVAILABLE, точка подключения — явный versioned numeric_study без автоматического
конвертера; при появлении исходника нужен отдельный аудит и новая явная версия.
Подстройки весов, цифровой формулы и обучения на известных исходах нет.

[Научная карта](../research/science/SCIENTIFIC_MAP.md) сохранена: вероятность и
статистика; решения; информация; причинность; физика времени (относительность,
причинная структура, стрела времени, ретрокаузальные модели и CTC).
[Источники и журнал доступа](../research/science/sources.json) описывают прежнюю
проверку, в интеграции доступность научных сайтов заново не удостоверялась.
Установленная теория, математическая возможность, интерпретация и подтверждённый
эффект различаются. Теория игр остаётся отложенной с условиями применимости.
[Опыт будущей случайной цели](../research/science/TIME_EXPERIMENT.md) спроектирован,
но не проведён; код его не подменяет. Даже превышение случайного уровня требует
исключения утечек и независимого повторения и само не устанавливает обратную
причинность. Учебный цикл не является физической петлёй времени.

**Технические тесты не доказывают прогнозную эффективность; гипотеза обратного
потока времени остаётся непроверенной.**
